# نشر النظام على نطاقك — خطوة بخطوة

## ما تحتاجه
1. **خادم Ubuntu 22.04/24.04** (1 vCPU و2 GB رام يكفيان) من Hetzner / DigitalOcean / Contabo أو مزوّد محلي، بعنوان IP عام.
2. **نطاق فرعي** مثل `erp.yourdomain.com` (لا تستخدم النطاق الرئيسي لو عليه موقعك).
3. إمكانية إضافة سجل DNS من مزوّد النطاق.

## الخطوات
1. **DNS:** أضف سجلاً من نوع `A`: الاسم `erp` والقيمة = عنوان IP للخادم. انتظر دقائق.
2. **ارفع المشروع للخادم** (من جهازك؛ استبدل العنوان):
   ```
   scp -r C:\erp root@SERVER_IP:/opt/erp
   ```
   (أو حمّل ZIP على الخادم وفكّه في `/opt/erp`). لا ترفع مجلد `data` المحلي إلا لو تريد نقل بياناتك الحالية (انظر "نقل بياناتك").
3. **على الخادم:**
   ```
   ssh root@SERVER_IP
   cd /opt/erp
   bash deploy/install.sh erp.yourdomain.com
   ```
   السكربت يتحقق من الـDNS، يثبّت Docker، يفعّل الجدار الناري (22/80/443)، يشغّل النظام خلف HTTPS تلقائي، ويجدول نسخة احتياطية يومية 02:30.
4. افتح `https://erp.yourdomain.com` وأنشئ حساب المدير باستخدام **رمز الإعداد** الذي طبعه السكربت (محفوظ أيضاً في `deploy/.env`). بعدها: الإعدادات ← تركيب هوية تريجون ← بيانات الإيميل.

## التحديث لاحقاً
```
cd /opt/erp && (ارفع الملفات الجديدة فوق القديمة، بدون مجلد data) 
cd deploy && docker compose up -d --build
```
البيانات في وحدة تخزين Docker `erp-data` ولا تتأثر بالتحديث.

## النسخ الاحتياطي
- يومياً داخل وحدة التخزين: `/var/lib/docker/volumes/deploy_erp-data/_data/backups/` (آخر 30 يوماً).
- **انسخها خارج الخادم** (جهازك أو تخزين سحابي) أسبوعياً على الأقل، أو فعّل لقطات الخادم عند المزوّد. الاسترجاع: أوقف النظام وضع الملف مكان `erp.db`.
- نسخة يدوية: الإعدادات ← تحميل النسخة الاحتياطية.

## نقل بياناتك الحالية من جهازك
أوقف النظام المحلي، ثم انسخ `C:\erp\data\erp.db` إلى `/tmp/erp.db` على الخادم، وشغّل:
```
cd /opt/erp/deploy
docker compose cp /tmp/erp.db app:/data/erp.db && docker compose restart app
```
(بعد ذلك لن تحتاج رمز الإعداد لأن المدير موجود.)

## أمان — لا تتجاوزها
- شغّل النظام **فقط خلف HTTPS** (الإعداد أعلاه يفعله).
- كلمة مرور المدير قوية، ولا تشارك حساب المدير.
- حدّث الخادم دورياً: `apt update && apt upgrade -y`.
- حماية البيانات الشخصية للموظفين مسؤوليتك؛ فعّل لقطات/نسخاً احتياطية مشفّرة لو أمكن.

## استكشاف الأخطاء
- `docker compose logs -f` لرؤية السجلات.
- الشهادة لا تصدر: تأكد أن سجل A صحيح وأن المنفذين 80 و443 مفتوحان.
