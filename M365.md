# الربط مع Microsoft 365 — المرحلة الأولى / Microsoft 365 link — Phase 1

يربط **مدير النظام** حسابه في النظام بحسابه في Microsoft 365 (Entra ID) عبر OAuth 2.0 Authorization Code + PKCE.
تسجيل الدخول للنظام **لا يتغير**: الربط يتم بعد الدخول بكلمة المرور، ولا يفتح النظام لأي حساب Microsoft.

An **administrator** links their ERP account to their Microsoft 365 (Entra ID) account with OAuth 2.0 Authorization Code + PKCE.
Signing in to the ERP **does not change**: the link is made after the normal password sign-in and never opens the ERP to a Microsoft account.

## 1. App registration (Microsoft Entra admin center)
1. **App registrations → New registration**: single tenant ("Accounts in this organizational directory only").
2. **Redirect URI** (platform *Web*): exactly `https://erp.trigon.ae/auth/microsoft/callback`.
3. **Certificates & secrets → New client secret**: copy its **Value** (not the ID).
4. **API permissions → Microsoft Graph → Delegated**: `openid`, `profile`, `email`, `offline_access`, `User.Read` — nothing else in Phase 1.

## 2. Server settings (`.env` next to `server.js`, never in git or the database)
```env
M365_ENABLED=1
M365_TENANT_ID=<Directory (tenant) ID>
M365_CLIENT_ID=<Application (client) ID>
M365_CLIENT_SECRET=<client secret Value>
M365_REDIRECT_URI=https://erp.trigon.ae/auth/microsoft/callback
M365_ENCRYPTION_KEY=<32 random bytes, base64>
```
Generate the encryption key once: `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`.
Keep it only in `.env`. If it is lost or changed, disconnect and connect again. Restart the system after editing `.env`.

If `M365_ENABLED=1` but a value is missing or invalid, the link stays closed and **Settings → Microsoft 365 link** lists which setting is missing (never its value).

## 3. Use (administrator)
**Settings → Microsoft 365 link → Connect Microsoft account** → sign in at Microsoft → back in Settings, "Linked to …".
**Check the link** calls Microsoft Graph `/me`; **Disconnect** removes the link and its tokens from the system.

## What is stored, and where
| Item | Where | How |
|---|---|---|
| Client secret, encryption key | `.env` only | never in the database, the browser, responses or logs |
| Access / refresh tokens | `m365_connections` | AES-256-GCM with `M365_ENCRYPTION_KEY` |
| OAuth state | `oauth_states` | SHA-256 hash only, single use, 10 minutes |
| PKCE verifier | `oauth_states` | AES-256-GCM |
| Backups (download, automatic, `scripts/backup.js`) | — | tokens and pending sign-ins are removed from the copy |

Audit log (`m365`): `config-change`, `connect`, `connect-failed`, `refresh-failed`, `disconnect`.

## Switching it off / rollback
Set `M365_ENABLED=0` (or remove the `M365_*` lines) and restart: the routes answer "off" and nothing calls Microsoft.
The two tables are additive and unused when off; they can stay. Also remove the app's consent in Entra if the link should be revoked there.
